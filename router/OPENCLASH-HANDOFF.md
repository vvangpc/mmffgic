# 家庭路由器交接 · GL-MT3600BE / OpenClash

适用项目版本为 0.5.13。请在连接家庭局域网的电脑上操作。家庭 Mac 的受保护流量（包括 Claude）应从面板中指定的 DMIT 公网地址出站；该出口不可用时，连接应失败。大陆直连、家庭局域网访问和路由器管理沿用家里的现有策略。VPS 升级由机主管理，调整家庭路由器无需点击 VPS 更新。

2026 年 11 月 25 日，0.5.13 面板上线后，默认用户的家庭日常源返回 4 个 DMIT 节点，应急源返回 1 个 CDN 节点；两份 YAML 均可解析，带原 ETag 再请求均返回 304。节点数会随授权、协议开关和上报变化。此项验证覆盖线上订阅服务。家庭路由器的实际握手、出站和断线保护，要在家中按下表验收。

## 从家里开始

在此公开仓库的本地副本中执行以下命令。macOS 和 Linux 可直接使用，Windows 可使用 Git Bash。只读脚本在家庭电脑上会提示输入已有的路由器 SSH 别名或局域网登录地址；也可以在 OpenWrt 上直接运行。

```sh
git pull --ff-only
sh router/check-openclash.sh
```

第一次连接时，按家庭已有记录核对路由器 SSH 指纹。盘点输出包含型号、固件、时间、OpenClash 状态、可用内核和防火墙后端。若走 LuCI 管理，按同样项目检查即可。请把下段交给家里的 AI：

> 阅读本文件和只读盘点结果。核对实际设备为 GL-MT3600BE，在家庭局域网内备份现有配置。沿用现有用户订阅，从真实生效的 OpenClash 配置入手，按下列要求完成适配、验证和必要的回滚。最后告诉我实际改了哪些本地文件、正常时从哪里出站、线路故障时是否成功阻断，以及备份放在哪。回报中请隐去订阅地址、凭据和设备私有标识。

## 谁负责什么

| 组件 | 职责 |
|---|---|
| Cloudflare 面板 | 按用户授权和已钉扎的 DMIT 身份生成家庭节点列表；修改出口钉扎是独立的面板管理操作。 |
| DMIT VPS | 代理出口。日常线路可以有多个协议入口；家庭 CDN 应急入口也应从同一台 DMIT 出站。 |
| GL-MT3600BE 上的 OpenClash / Mihomo | 使用节点列表，决定本机策略组、规则顺序、DNS 和流量接管。OpenClash 重载后的最终配置决定实际行为。 |
| 家庭路由器防火墙 | 代理内核停止时仍能保护指定设备或网段。机主之前的 RackNerd 公网测试验证了另一台 VPS 的工作链路，家庭出口仍以 DMIT 为准。 |

## 接入两个家庭节点源

从机主已登录的面板「订阅」取家庭用户已有的地址，保留其 HTTPS 来源和原有 token，按下表设置查询参数。真实地址只保存在家庭设备的私有配置中。已存在的查询参数用 URL 编辑器替换，检查最终只有一个 `format` 和一个 `scope`。

| 用途 | 面板路径示意 | 本地使用方式 |
|---|---|---|
| 日常 | `/sub/<token>?format=clash&scope=dmit-daily` | 作为日常代理节点源，供 DMIT 自动组引用。 |
| 手动应急 | `/sub/<token>?format=clash&scope=dmit-cdn` | 单独作为 CDN 节点源，由机主手动选择。 |

两个响应的顶层均为 `proxies`。保留家庭主 YAML 和 OpenClash 的覆写源，将节点接到 `proxy-providers`；不要用节点列表覆盖整份家庭主配置。按现有北京时间 03:00 的刷新安排核对实际时区和定时机制。两份缓存使用不同文件。面板返回 200 时先解析并验证非空节点列表；304 沿用缓存；503、超时或解析失败时保留上一份有效缓存。首次配置且没有有效缓存时，受保护策略保持拒绝。字段及引用方式见 [Mihomo 节点源](https://wiki.metacubex.one/en/config/proxy-providers/)和[策略组](https://wiki.metacubex.one/en/config/proxy-groups/)。

## 调整顺序

1. **建立回退点。** 从有线或可信 LAN 保持到 LuCI/SSH 的管理会话。备份当前 OpenClash 配置、覆写及脚本、两个节点缓存、UCI 的 OpenClash/防火墙设置，以及现用的自定义防火墙规则。备份保留权限，私下保存到家庭电脑。记录当前选中组、LAN 管理连通性和受保护设备的基准出口。
2. **核对节点和出口。** 从面板读取当前钉扎的出口 IPv4 与节点名称。用现有 Mihomo 内核解析候选配置，核对实际启用的协议、TLS、指纹及节点域名解析。项目的家庭节点格式按 Mihomo 1.19.34 做过兼容验证，其他内核版本以本机解析和实际握手为准。保留当前可用节点缓存，切勿把证书校验失败当成可用线路。
3. **接回家庭规则。** 日常自动组选 DMIT 日常源，应急组仅引用 CDN 源。受保护规则在泛域名、大陆直连和最终匹配规则前生效。检查所有可达的嵌套组和手选项，移除可通往 DIRECT、COMPATIBLE 或其他 VPS 的回退路径，保留明确的拒绝出口。测试无可用节点时的最终行为。保留原有 LAN、管理地址及其他设备的直连策略。
4. **检查代理停止时的保护。** 在本机实际使用的 fw4/nftables 或旧版后端上核对已有断线保护，覆盖受保护设备的 IPv4、IPv6、DNS 以及 TCP/UDP。设备开有独立 DoH、QUIC 或其他可能影响域名识别的设置时，核对它是否仍受设备级策略约束。仅凭域名规则或 OpenClash 的开关无法证明停核后仍受保护。涉及整机、整段 LAN 的策略调整，先核对保护对象及保留的局域网服务。
5. **先校验，再切换。** 用家中实际内核的 `-t` 校验候选配置；涉及防火墙时先做对应后端的语法检查。使用现有 OpenClash 工作流加载，避免直接修改下一次重载会覆盖的生成文件。保存一份脱敏的变更清单。

## 验收与回滚

| 在家庭 Mac 上验证 | 通过条件 |
|---|---|
| 日常出口 | 用与受保护流量相同的策略访问面板的 `/api/whoami` 和另一个可信出口回显服务，两处都显示面板钉扎的 DMIT IPv4；同时在 OpenClash 连接页确认命中预期组。 |
| CDN 手动切换 | 切到应急组后真实 HTTPS 请求成功，出口仍为同一 DMIT；再切回日常。 |
| 刷新失败 | 在临时候选配置中模拟节点源不可用，原缓存仍可用且未被空列表覆盖。在无历史缓存的测试组中确认受保护请求失败。 |
| 断线保护 | 在有独立 LAN 管理通道和恢复措施的窗口测试。先验证所有 DMIT 入口不可用，再短暂停止测试所依赖的代理内核，分别检查新的 IPv4/IPv6 受保护连接和 DNS 是否外泄。公网直出视为失败，LAN 管理仍应可达。 |
| 恢复 | 恢复 OpenClash 后新连接重新显示 DMIT 出口；检查大陆直连、原有 LAN 服务正常，并验证一次正常订阅刷新。 |

出现意外出口、LAN 管理受影响或配置无法加载时，停止切换。通过保留的本地管理会话恢复上述备份的覆写源、主配置、缓存和防火墙设置；只重载本次改动涉及的组件，再重复基准检查。没有实测的项目在交接结果中写「未验证」。
