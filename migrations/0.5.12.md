# 旧 VPS 手动迁移至 0.5.12 发布公钥

0.5.12 起使用新的 Ed25519 发布密钥。已安装的 VPS 仍信任旧公钥，会拒绝新签名。每台旧 VPS 只需迁移一次。新装的 0.5.12 已内置新公钥。电脑、手机和 OpenClash 路由器只下载订阅，无须安装此公钥。

## 1. 选择操作时间

用受信任的 SSH 或服务商控制台登录目标 VPS 的 root 终端，执行 `sb version` 并核对机器。若要由自己决定升级时间，在迁移公钥前进入 `sb → 6 更新设置`，确认脚本自动更新已关闭。远控经过这条线路时，可以先完成换钥，等能接受短暂断流时再升级。

## 2. 验证迁移工具，再替换本机公钥

从本次发布的固定版本下载工具。在 root 终端完整执行下列命令。校验失败会停止。成功时脚本将原公钥保存在安装目录的 `etc/release-before-0.5.12.pub`，原子替换 `lib/release.pub`，然后输出新指纹。此步骤只操作发布验证公钥，可以重复执行。

```bash
curl -fLsS --retry 3 https://raw.githubusercontent.com/vvangpc/mmffgic/v0.5.12/migrations/0.5.12-key.sh -o /root/mmffgic-migrate-key.sh &&
  printf '%s  %s\n' '6552793ce2c3c9fbd33434828f2280da72567476a56d6c38e9a334aecbcc779d' /root/mmffgic-migrate-key.sh | sha256sum -c - &&
  bash /root/mmffgic-migrate-key.sh apply
```

以下是公钥 DER 编码的 SHA-256 指纹。遇到未知指纹时，脚本停止，请核对所登录的机器及其安装来源。

| 公钥 | 指纹 |
| --- | --- |
| 旧 | `9324e93b19b8e1459a63beabe64310faa0660851d7a98e1d6c9a7cb399970950` |
| 新 | `c65e3487209c36490d6a593f447c652f12d9f70f6f1de073885d80fe23a53ab1` |

如果决定推迟换钥，可在**升级前**执行 `bash /root/mmffgic-migrate-key.sh restore`。已经升级的机器使用新公钥。

## 3. 在你选定的时间升级

打开面板，选择 **运维 → 目标 VPS → 组件 → 脚本 → 更新**。0.5.11 也可以在目标机器执行 `sb update self`。0.5.2 等只支持旧清单格式的版本，请按面板提示走 SSH 首次升级流程。面板和命令都使用配置的更新源，下载当时公开的最新版。

升级后，在同一台 VPS 执行 `sb version` 和 `sb health`，再用客户端测试该机的一条线路。若失败，先查看面板任务结果和实际版本，再决定重试。
